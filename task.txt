Task 3: The "Product Finder" (req.params & 404 Error handling)
Create an array of products in server.js:
[{ id: 101, name: "Keyboard", price: 500 }, { id: 102, name: "Mouse", price: 300 }]

Goal: Create a route /api/products/:id.

Condition 1: If a user visits /api/products/101, remember to convert req.params.id from String to Number, find the product, and send its data.

Condition 2: If the user visits /api/products/999, the server must send a 404 status code with this exact JSON: { error: true, message: "Product missing!" }.

Task: The "Student Profile Updater" (Params + Body Combo)

Setup: Create an array of students directly in your server.js file:
[{ id: 1, name: "John", course: "HTML" }, { id: 2, name: "Sarah", course: "CSS" }]

Goal: Create a PUT route: /api/students/:id

The Concept: This task combines two concepts. You need req.params to know WHO to update, and req.body to know WHAT new information to put there.

Condition 1: A user sends a POST request to /api/students/1 using Thunder Client. In the JSON body, they send: { "newCourse": "React" }.

Condition 2: Your server must extract the id from the URL, find the matching student in the array, and update their course to the new one sent in the body.

Condition 3: Send the updated student object back in the JSON response.










Setup: Set up an Express server in your server.js file and include the JSON parsing middleware. Create an empty array to act as your mock database: const gymMembers = [];

Goal: Create a complete Gym API with 3 distinct routes combining POST, query strings, and dynamic parameters.

Route 1 (Add Data - req.body): Create a POST route at /api/members.

A user will send a JSON body via Thunder Client (e.g., { "name": "Rahul", "plan": "VIP" }).

Your task is to extract this data, assign a unique id (you can use Date.now()), and .push() it into the gymMembers array.

Send a success response returning the newly created member object.

Route 2 (Filter Data - req.query): Create a GET route at /api/members.

If a user sends a GET request to /api/members without queries, return the entire gymMembers array.

If a user sends a request to /api/members?plan=VIP, use .filter() to return ONLY the members who have the "VIP" plan.

Route 3 (Find Specific Data - req.params): Create a GET route at /api/members/:id.

If a user visits /api/members/123456789, extract the ID from the URL using req.params.

Convert it to a Number and use .find() to return that specific member's details.

If the ID does not exist, return a 404 status with an error message.
First, make a POST request in Thunder Client to add 2-3 members (make sure some are "VIP" and some are "Basic").

Next, make a GET request to /api/members to verify the data was successfully pushed to the array.

Then, test your query filter by requesting /api/members?plan=VIP.

Finally, copy an ID from your array and test your params route: /api/members/<pasted_id>.
