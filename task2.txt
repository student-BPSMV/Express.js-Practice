🟠 Level 3 — Route-Specific Middleware
Q7. Admin Dashboard

Create:

GET /dashboard

and middleware:

checkAdmin

The dashboard should only be accessible when:

/dashboard?role=admin

If the user is not an admin, send:

You are not authorized to access this page

Important: Apply the middleware only to /dashboard, not to every route.

Q9. Serve Admin HTML

Create:

Admin.html
AccessDenied.html

Create:

checkAdmin

When the user visits:

/admin?role=admin

serve Admin.html.

If the role isn't admin, serve AccessDenied.html.

So:

/admin?role=admin
        ↓
Admin.html

and:

/admin?role=user
        ↓
AccessDenied.html

checkUser

🔴 Level 5 — Middleware Order
Q11. Understand Middleware Order

What will happen when this code runs?

app.use((req, res, next) => {
    console.log("Middleware 1");
    next();
});

app.get("/", (req, res) => {
    console.log("Home Route");
    res.send("Home");
});

app.use((req, res, next) => {
    console.log("Middleware 2");
    next();
});

When you visit:

http://localhost:4000/

What will appear in the terminal?

Don't run it first — predict the output.

Q14. Student Portal Middleware

Create an Express server with these routes:

/
 /students
 /dashboard
 /admin

Create the following middleware:

1. Logger middleware

For every request print:

GET /dashboard
GET /students

using:

req.method
req.url
2. Student middleware

For:

/students?name=Nandini

check whether name exists.

If it exists → next().

Otherwise:

Student name required
3. Admin middleware

For:

/admin?role=admin

allow access.

For:

/admin?role=user

send:

Access denied
4. 404 middleware

At the very end, handle unknown routes:

Page not found
